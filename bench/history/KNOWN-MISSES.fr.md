# Pertes connues dans le banc Sol (30 septembre 2026)

Périmètre : les 22 fixtures versionnées dans `bench/cases.json`. Une économie ne compte que si l'oracle déclaré est entièrement conservé. Deux cas sont derrière RTK ; aucun n'a d'échec technique d'exécution, et Headroom ne gagne aucun de ces cas. Les six cas de code à économie nulle sont des égalités. Ces chiffres décrivent ce corpus, pas une performance générale. Le rejeu complet courant utilise le commit de fusion `df30334` ; ses mesures sont dans `bench/resultats.json` et `bench/RAPPORT.md`. L'ancien corpus de `bench/resultats-avant.json` ne permet pas de comparer ces captures (`bench/README.md:22`).

## `dotnet_ok` — synthèse de réussite encore longue

- **Constat :** sur la vraie capture de `dotnet test` (`bench/corpus/dotnet_ok.txt:1-5`), LM Resizer supprime les lignes de préparation mais conserve la longue ligne `Passed!` et ajoute une référence à la sortie brute. L'oracle `65 passed` reste présent (`bench/cases.json:27-34`). RTK produit une synthèse plus courte.
- **Mesure exacte :** `bench/resultats.json:113-147` : 111 jetons en entrée, 55 en sortie pour LM Resizer (50,45 % d'économie), 21 pour RTK (81,08 %) ; oracle conservé à 100 % par les deux. Headroom garde les 111 jetons (`bench/resultats.json:150-165`). Comparaison arrondie dans `bench/RAPPORT.md:49`.
- **Cause probable :** la route .NET structurée traite les fichiers TRX ou binlog, puis renvoie `None` si aucun n'est disponible (`src/parity_filters.rs:103-121`). La route console choisit le filtre TOML (`src/main.rs`), dont la règle `Passed!` conserve la ligne d'origine (`src/main.rs`) ; `apply_toml_filter` rassemble les lignes retenues sans condenser les comptes (`src/main.rs`).
- **Piste :** analyser le verdict console de réussite et émettre une synthèse courte qui garde les nombres de tests réussis, échoués, ignorés, le total et la portée exécutée. Conserver les blocs d'échec et les emplacements source actuels ; tester plusieurs sorties .NET réelles.

## `git_diff` — ancienne perte, corrigée

- **Constat initial :** sur le vrai patch de deux fichiers (`bench/corpus/git_diff.txt:1-20`), le filtre gardait chaque en-tête `diff --git` ainsi que les chemins `---` et `+++`. Les changements et les huit faits de l'oracle (`bench/cases.json:100-114`) étaient présents, mais ces doublons consommaient des jetons.
- **Mesure antérieure (révision `9e73489`) :** 195 jetons en entrée, 133 en sortie pour LM Resizer (31,79 % d'économie), 125 pour RTK (35,90 %) ; les deux conservaient l'oracle déclaré.
- **Cause et correction :** `filter_diff_summary` gardait les trois en-têtes de chemin (`src/main.rs`). La regex générique d'échec interprète aussi le mot `diff` de `diff --git` comme un diagnostic (`crates/lm-resizer-core/src/transforms/diagnostic_gate.rs:18-23`) : retirer seulement cette ligne déclenchait le repli sur la sortie brute (`src/main.rs`). Le filtre omet désormais `diff --git` seulement quand le bloc contient `---` et `+++`, et la garde ignore cet en-tête structurel. Un diff binaire ou tronqué conserve son en-tête Git (`src/main.rs`).
- **Rejeu complet actuel à trois outils :** même fixture et même tokenizer `o200k_base` : 195 → 103 jetons (47,18 % d'économie) pour LM Resizer, contre 125 jetons (35,90 %) pour RTK, avec l'oracle déclaré complet pour les deux (`bench/resultats.json`, `bench/RAPPORT.md`). Le test de régression est `git_diff_capture_omits_redundant_file_headers_without_losing_patch_facts` dans `src/main.rs`.

## `compile_error` — la garde des diagnostics rétablit toute la sortie

- **Constat :** la vraie sortie d'échec de `cargo build` (`bench/corpus/compile_error.txt:1-10`) est rendue à l'identique. LM Resizer conserve l'emplacement, le code d'erreur et les types en conflit (`bench/cases.json:229-239`), mais n'économise aucun jeton. RTK conserve le même oracle dans une sortie plus courte. Le CLI renvoie le code 101 attendu : il s'agit d'une perte de compression, sans échec technique d'exécution.
- **Mesure exacte :** `bench/resultats.json:827-861` : 106 jetons en entrée, 106 en sortie pour LM Resizer (0 %), 78 pour RTK (26,42 %) ; oracle conservé à 100 % par les deux. Headroom garde aussi 106 jetons (`bench/resultats.json:864-879`). Comparaison arrondie dans `bench/RAPPORT.md:61`.
- **Cause probable :** la route `cargo build` appelle `filter_diagnostics` (`src/main.rs`, `src/main.rs`). Sur cette capture, la vérification après filtrage trouve une ligne supprimée qui correspond au signal d'échec général et rétablit le texte brut (`src/main.rs`, `src/main.rs`). Un rejeu local indique `cargo_diagnostics:diagnostic-guard` et 390 → 390 octets. Le banc ne passe pas `--raw-on-failure` ; cette option n'explique donc pas le résultat (`bench/src/main.rs:499-507`).
- **Piste :** regrouper chaque diagnostic du compilateur par emplacement, code, message et extrait source, puis distinguer les indications standard comme `rustc --explain`. Comparer ces faits structurés avant et après compression pour accepter une forme plus courte équivalente ; couvrir les erreurs multiples et les notes.
