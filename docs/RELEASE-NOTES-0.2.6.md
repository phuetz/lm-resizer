# LM Resizer 0.2.6

La 0.2.5 est publiée. Cette version corrige deux failles de sécurité relevées par un audit, ajoute `smart --ast`, corrige les vues `git log` et pytest, retire les chemins du constructeur du binaire Linux et rend le rejeu du banc exécutable en une commande. Détail dans le CHANGELOG.

- Sécurité : `rewrite-shell` pouvait produire une ligne dont `sh -c` exécutait du shell injecté par un argument (`head -n 1 '\" ;touch X;#'`) ; les arguments sont maintenant cités en apostrophes POSIX et toute ligne qui ne se redécoupe pas à l'identique reste inchangée. La clé d'API n'est plus passée en argument au proxy lancé par `wrap` (visible par `ps`) : environnement ou `--api-key-file` (0600). Le proxy ne suit plus les redirections de l'amont, vérifie `Host` et refuse une écoute hors boucle locale sans `--allow-non-loopback` ; `sanitize-provider-fixture` masque `x-api-key` ; l'état local est créé en 0700/0600. Mettez à jour avant d'utiliser `rewrite-shell` ou le hook sur des dépôts non fiables ; fichiers existants : `chmod -R go-rwx ~/lm-resizer`.
- Hooks : le hook Claude ne renvoie plus `permissionDecision: allow` (l'invite d'approbation revient ; seul Codex le reçoit), mais la réécriture fait échapper la commande aux règles `deny` écrites pour la forme d'origine : ajoutez `Bash(*exec -- cargo test*)` (voir `SECURITY.md`). `tail -f`, `npm run dev`, `docker compose up` et `journalctl -f` ne sont plus réécrits.
- `cargo test` : `FAILURES (n)` compte les tests en échec, le bilan n'est plus doublé et `error: test failed, to rerun pass …` est conservé. Un `[tee:<id>]` affiché dit `lm-resizer tee read <id>`, et la dernière ligne d'une sortie longue n'est plus supprimée.
- pytest : chaque échec n'est listé qu'une fois, et `python -m pytest` / `uv run pytest` sont raccourcis.
- Lanceurs de tests (proposition en attente) : un lanceur de tests qui se termine par le code 0 sort brut ; un test réussi peut écrire n'importe quoi (un `git log` relayé, un avertissement de sécurité) que la vue réduisait au bilan. Un échec garde la vue réduite.

- `lm-resizer smart <fichier> --ast` résume localement (tree-sitter, sans modèle ni réseau) un fichier Rust, Python, JavaScript ou TypeScript : imports, types, signatures et ligne réelle de chaque déclaration, corps omis. Source invalide ou extension inconnue : repli annoncé en première ligne (`[smart AST: repli …]`) puis sortie historique. Sans `--ast`, `smart` répond octet pour octet comme en 0.2.5. Réduction mesurée sur trois fichiers réels du dépôt : 82,29 %, 93,47 % et 89,08 % en octets. Les attributs Rust `#[…]` ne sont plus présentés comme documentation, et un champ privé JavaScript `#x` n'est plus pris pour un commentaire.
- `git log` (format par défaut) montrait seulement le premier commit (1 commit sur 40 et, avec `--stat`, 1 fichier sur 316 visibles sur un dépôt réel, d'où une « réduction » de 99 %). La vue affiche désormais chaque commit (40/40 sur ce dépôt) ; `--stat`, qu'une première correction raccourcissait (9 à 58 % de jetons selon les dépôts), sort maintenant brut. `git log` n'est raccourci qu'en appel direct simple : `git [-C dossier] log` lancé par `exec`, avec seulement `--decorate`, `--all`, `-n N`, `-N`, des révisions, des plages ou `-- chemins`, sans clé `format.*`/`log.*` dans `git config` ; la vue est refusée si un hash d'en-tête manque. Toute autre forme sort brute, octet pour octet : autre option (`--format`, `--stat`, `-p`…), `--no-pager`, `-c`, alias, `pipe`, `tool-output`, wrapper (`env`, `timeout`, `xargs`…), shell, script, commande assemblée par variables. Plus largement, un programme sans vue native n'est plus résumé de lui-même : il sort brut (le résumé reste disponible par `lm-resizer summary -- <commande>`), de même que les lanceurs de recettes (`make`, `npm run`, `npm test`, `cargo run`, `uv run`…), sauf harnais nommé (`npm run vitest`, `uv run pytest`). Lanceurs de tests : quand l'argv demande d'afficher la sortie des tests (`cargo test -- --nocapture` ou `--show-output`, `pytest -s` ou `--capture=no`, `go test -v` ou `-json`, `jest|vitest --silent=false`, `dotnet test -v d`…), ou que le lanceur n'a pas de capture (`rspec`, minitest, `mvn test`, `playwright test`), la sortie est brute : un vrai `cargo test -- --nocapture` qui imprimait un `git log` de 23 commits ne gardait que son bilan. Limites : la sortie qu'un test en échec fait afficher sans drapeau suit la vue du lanceur (pytest `Captured stdout call`, `console.log` de jest), et les visionneuses de journaux (`docker logs`, `journalctl`) gardent leurs vues ; le brut se récupère par `tee read` (voir `docs/KNOWN-MISSES.md`). Le brut reste dans tee. Conséquence sur le banc : les cinq captures `git log` de plusieurs commits ne valent plus 91 à 97 % mais 0 %.
- `bench/real/rejouer.sh` rejoue les 61 captures en une étape (Python isolé avec tiktoken, comparaison construite depuis l'archive épinglée, dossier de rejeu neuf) et affiche médiane, moyenne, bruts récupérés et codes du producteur. Le verdict du script exige désormais les 61 captures et des seuils (médiane ≥ 4,87 %, moyenne ≥ 27,60 % ; ceux de la 0.2.5, 25,18 % et 34,68 %, supposaient des vues `git log` qui cachaient des commits). Rejeu de cette préparation : médiane 4,87 % (0.2.5 : 25,18 %), moyenne 27,61 % (34,68 %), 61/61 bruts récupérés et codes du producteur conservés, 34/61 vues strictement égales à l'oracle (41/61) : `visible-pytest` et `fresh-pytest` changent parce que l'oracle liste lui aussi deux fois le même échec, les six captures `git log` parce que la vue montre chaque commit, et les deux captures `npm test` parce qu'elles sont brutes. La médiane et la moyenne sont inférieures à celles de la 0.2.5 pour ces seules raisons ; la médiane (15,81 %) et la moyenne (32,61 %) de l'oracle de comparaison dépassent celles de LM Resizer.
- Audit du 9 octobre, hook : une commande qui peut demander un mot de passe ou ne pas se terminer n'est plus enveloppée (`git push|pull|fetch|clone`, `cargo run`, `go run`, `docker run -it`, `sudo`, `terraform apply` sans `-auto-approve`…) ; `exec` gardait la sortie jusqu'à la fin, l'invite n'apparaissait pas. Le crochet Cursor répond `permission: ask` au lieu de `allow` (« proceed » pour Cursor) ; la documentation de Cursor dit `ask` non appliqué pour `preToolUse` : effet non vérifié dans Cursor. Une commande reçue en tableau reste un tableau : ses éléments ne sont plus recollés avec des espaces (`*` n'est plus développé). `uninstall-hooks --client all` retire aussi les crochets Gemini, Copilot et Cursor ; `uninstall --client all --scope project` retire l'entrée MCP. Sous Linux, `kill -9` d'`exec` tue aussi l'enfant (pas ses propres enfants).

Poids : le binaire release grossit d'environ 12 % avec l'analyseur syntaxique. Les dépendances ajoutées (tree-sitter et ses grammaires, streaming-iterator) sont sous licence MIT ou MIT/Apache-2.0 et figurent dans `THIRD-PARTY-NOTICES`.

Limites : le proxy n'authentifie pas ses clients (tout compte local qui atteint le port dépense la clé amont) et l'installateur ne vérifie qu'une somme SHA-256 sans signature ; les lignes de corps d'un `git log` sont coupées à 100 caractères dans la vue (le titre ne l'est jamais) (voir `docs/KNOWN-MISSES.md`). Le JSON de `smart --ast` donne des jetons estimés en octets ÷ 4 (`token_count_method: "approximate"`), contrairement au reste du produit. Les gains du banc sont limités au corpus déclaré ; aucun gain universel ni coût fournisseur n'est promis. La purge automatique de tee n'est pas incluse. Windows n'a pas été rejoué pour cette préparation.
