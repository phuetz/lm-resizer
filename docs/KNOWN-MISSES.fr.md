# Limites des vues natives

La migration des filtres est en cours. Les mesures antérieures ne décrivent pas cette version. Voir [le banc](../bench/native/README.md) pour les écarts mesurés, les commandes restantes et la récupération du brut.

## `git log` : ce qui reste brut

Depuis 0.2.6, `git log` n'est compressé que si le **format par défaut est prouvé**. C'est le cas seulement pour un appel direct de `git log` lancé par `exec` (ou `lm-resizer git log`) : ni `sh -c`, `&&`, `|` ou `;`, ni `--format`, `--pretty`, `--oneline`, `-z`, `--graph`, ni option globale `-c` ou `--config-env`, et `git config --get-regexp '^(format|log)\.'`, lu avec les mêmes options globales (`-C`, `--git-dir`…) dans le dossier de la commande, ne trouve aucune clé (`format.pretty`, `log.date`…). Alors la vue montre chaque commit (en-tête, `Merge:`, `Author:`, `Date:`, titre et trois lignes de corps au plus ; le reste est compté dans `[+N message lines omitted]`, les pieds `Signed-off-by` et `Co-authored-by` sont retirés ; `--stat` ajoute chaque fichier, sans les barres de proportion). Dans tous les autres cas la sortie est **brute** : `pipe` et `tool-output` n'ont pas de ligne de commande fiable et ne reconnaissent jamais un `git log` par son contenu, une commande composée par un shell n'est pas un appel direct, et une sous-commande git sans vue native (alias compris) est rendue brute. Les options globales de git (`--no-pager`, `-C <dossier>`) sont lues avant la sous-commande. Le patch demandé (`-p`, `-u`, `-U<n>`, `--patch…`, `--cc`, `-c`, `-L`, `--word-diff`) garde son codec, qui ne tronque jamais et n'est retenu que s'il se déplie en l'original exact. **Garde finale, sur toutes les voies** : si une vue perd un hash de commit ou un sujet non vide que le brut présente (en-têtes `commit`, lignes `<hash> <sujet>`, hashes seuls), le brut est rendu ; la garde ne reconnaît le contenu que pour refuser une vue, se tromper la rend inutile et jamais dangereuse. Limites : la configuration est lue là où `lm-resizer` s'exécute ; un titre est coupé à 100 caractères dans la vue (la garde le voit alors comme un sujet perdu et rend le brut) ; et la garde parcourt toute sortie qui contient des identités (mesuré sur 18 Mo et 100 000 commits : 3,6 s et 430 Mo en `exec`).

Conséquence mesurée sur le banc de 61 captures : les cinq captures `git log` de plusieurs commits, passées par `pipe`, passent de 91 à 97 % de « réduction » (premier commit seul, comme l'oracle de comparaison, qui le fait toujours) à 0 %. Médiane 30,43 → 4,87 % et moyenne 35,14 → 28,39 % par rapport à la préparation avant correction de `git log`.
