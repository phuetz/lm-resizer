# Known misses in the Sol 6.1 comparison (updated 30 September 2026)

Scope: the 22 versioned fixtures and declared oracles in `bench/cases.json`. A saving counts only when the oracle is fully retained. The original three-tool benchmark (`142a9ef0aa71b6b1892c4f31617e00e354c16eba`, `bench/resultats.json`, historical tables in `bench/RAPPORT.md`) had three losses to RTK. PR #28 fixed `git_diff`; the local replay below reduces the two remaining losses, without overtaking RTK. Headroom wins none of these cases. The six code fixtures with zero saving are ties. These figures describe this corpus, not general performance.

The focused replay starts at `30d563d` (already containing PR #28). It uses the existing harness's `run_all`, command shims, oracle checks, normalization and `tiktoken-rs` 0.11 `o200k_base`, restricted to LM Resizer. `exec` does **not** use `--raw-on-failure`; the raw reference is included in the token count. Baseline debug outputs reproduce the historical hashes for 21 cases; `git_diff` is already 103 tokens. Final release outputs match all 22 final debug outputs. RTK and Headroom were not rerun: their figures remain historical references. Before, after each fix, binary and fixture hashes, and all output fingerprints are in `bench/resultats-pertes-2026-09-30.json`. `bench/resultats-avant.json` uses an older corpus and cannot serve as the baseline for these captures.

## `compile_error` — reduced, still behind RTK

- **Before:** The real failed `cargo build` capture was returned verbatim: 106 input/output tokens, 0% saving. The three oracle facts are `src/main.rs:2:22`, `error[E0308]`, and “expected `i64`, found `String`”. The CLI exits with 101 as declared; this is a compression loss, not an execution error. Historical RTK output is 78 tokens (26.42% saving); Headroom is 106.
- **Cause:** `filter_diagnostics` kept only three lines after a diagnostic. It cut the source frame, including the type mismatch, so `first_lost_failure_line` restored the raw capture (`cargo_diagnostics:diagnostic-guard`).
- **Fix:** `filter_cargo_diagnostics` handles numbered rustc errors conservatively: it keeps every nonempty diagnostic line, including complete source frames, notes, help, multiple errors and unknown text. It trims outside whitespace and removes empty gutters. The exact standard `rustc --explain Edddd` hint is redundant only when that error header is still present; other hints remain guarded. Cargo output without numbered rustc errors keeps the previous filter.
- **After:** 106 → **93 tokens**, **12.26% saving**; 13 fewer output tokens. All three oracle facts, the source statement, the annotation explaining the expected type, the package/bin failure verdict and exit code 101 remain. SHA-256 of the output: `d66636058a657f6a7532fce29216f072ce34376664f1404c3c7d9eb09ef8706d`. RTK is still shorter by 15 tokens. No claim of the shortest possible faithful representation is made.
- **Tests/evidence:** `compile_error_capture_keeps_complete_diagnostic_without_boilerplate` was observed failing before and passing after. Additional tests cover multiple diagnostics, late notes/help, unknown error codes and the exact hint guard. After this fix alone, all 21 other output hashes are unchanged.

## `dotnet_ok` — reduced, still behind RTK

- **Before:** The real `dotnet test` capture has 111 input tokens. The TOML console filter kept the entire `Passed!` line plus a raw reference: 55 output tokens, 50.45% saving. The oracle declares `65 passed`. Historical RTK output is 21 tokens (81.08% saving); Headroom is 111.
- **Cause:** The structured .NET route handles TRX/binlog files but this capture has neither. `apply_toml_filter` selected the long console verdict without rewriting its counts.
- **Fix:** After the existing structured routes, `filter_dotnet_success` recognizes complete successful console verdicts. It checks zero failures and `passed + skipped = total`, then keeps each assembly, framework, all four counts and duration. A mixed failure, warning, unrecognized verdict, inconsistent/overflowing count or unknown duration keeps the existing filter and diagnostic guard. The guard accepts a rewritten success line only if its entire parsed summary remains visible.
- **After:** 111 → **40 tokens**, **63.96% saving**; 15 fewer output tokens than the baseline (27.27% less output). The oracle is complete; so are `0 failed`, `0 skipped`, `65 total`, `Atlas.Tests.dll`, `net8.0`, and `41 ms`. SHA-256: `90c991f84e12dc5613bd8a29b00c06498172fa6bf185c1096b54548be717f917`. RTK is still shorter by 19 tokens. Preserved scope/counts/duration and raw recovery contribute to the remaining size.
- **Tests/evidence:** `dotnet_success_capture_compacts_counts_scope_and_duration` was observed failing before and passing after. Tests also cover multiple assemblies, skipped tests, decimal durations, incomplete summaries, failures, warnings, unknown formats and invalid counts. After both fixes, the 20 other case hashes are unchanged, including `dotnet_fail` and `git_diff` at 103 tokens. All 22 LM Resizer oracles remain complete.

## `git_diff` — fixed in PR #28

The original two-file patch had 195 input tokens and 133 output tokens (31.79% saving), compared with RTK's 125 (35.90%). `filter_diff_summary` omitted `diff --git` only when both `---` and `+++` exist in the file block; the guard excludes that structural header. Binary/truncated diffs retain it. The focused PR #28 replay measured **103 output tokens (47.18% saving)**, with all eight declared oracle facts. The 30 September baseline and final replays confirm 103 tokens and an identical fingerprint. The historical three-tool JSON still records 133; it has not been relabeled as a new three-tool run.
